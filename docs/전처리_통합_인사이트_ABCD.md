# 전처리 통합 인사이트 — A(가격)·B(연령성별)·C(계절명절)·D(지역배송) 취합본

## 0. 한눈에 보기 — 지금 팀이 결정해야 할 7가지

실제 전처리 코드를 짜기 전에 아래는 "누군가 임의로 정하고 넘어가면 안 되고 팀이 합의해야 하는" 항목이다.

| # | 결정 사항 | 제안한 파트 | 권장안 | 왜 중요한가 |
|---|---|---|---|---|
| 1 | **분석 단위를 품목행이 아니라 무엇으로 할 것인가** | A, B 공동 발견 | `회원번호 × index_date`(B안 채택 권장) | 품목행 그대로 쓰면 다품목·고빈도 고객이 과대 대표됨(A·B 독립적으로 같은 결론) |

| 3 | **구독여부 재분류 시점 원칙** | B(가장 명확히 제기) | 반드시 `index_date` **이전** 행동만 사용 + `treatment_source` 컬럼으로 출처 남기기 | 안 지키면 target leakage. A가 발견한 적립금 자기선택편향과 같은 종류의 함정 |

| 5 | **11/10~14 데이터 결측(홀드아웃 구간)** | C 신규 발견 | PM 공유 후 원인 확인, Step0 assert에 반영, Step6 분할 영향 재검토 | 팀이 아직 모르던 이슈. 홀드아웃(10~11월) 안에 있어서 영향 큼 |
| 6 | **"추석 직후 -63.8%" 수치 재검증** | C 신규 발견 | 원 산출자에게 카테고리 범위/요일통제 여부 확인, 발표자료 문구 재검토 | 요일효과 미통제 가능성 발견, 동일 조건 재현 실패 |
| 7 | **가정 기반 매핑(배송권역 Tier, 제철 임계값 65%)** | D, C | 가정임을 문서에 명시, 민감도 분석 병행, 실제 물류/외부자료로 교차검증 권고 | 데이터에 없는 정보라 두 파트 모두 스스로 "이건 가정"이라고 못박음 |

## 1. 전체 팀에 영향 주는 핵심 발견 (파트 구분 없이 공유 필요)

### 1-1. 품목행(668,111) ≠ 실제 주문(약 191,018건) — A·B 독립 교차검증
- A: 회원번호+주문일시로 재집계 시 **191,018건**, 주문당 평균 품목 3.34개, 73.6%가 다품목
- B: 동일 방식으로 **191,018건**(정확히 일치), 회원당 구매일수 중앙값 6일
- **재구매 간격 중앙값도 두 파트 모두 5일로 일치** → 서로 다른 사람이 독립적으로 계산해서 같은 숫자가 나왔다는 건 이 구조 문제가 진짜라는 강한 근거. 목표 슬라이드의 "30일=평균주기 6배" 서술과도 정합(5일×6=30일).
- **결론**: `구매금액`, `가격구간`, `연령×성별 세그먼트` 등 A/B가 다루는 모든 피처는 품목행이 아니라 주문(또는 그 이상 집계 단위)에서 계산해야 함.

### 1-2. Treatment(구독여부) 자기선택편향 — A(수치)와 B(시점 문제)가 서로 다른 각도에서 같은 결론
- A: 적립금 한 번이라도 쓴 고객은 평균 주문 25.9회, 안 쓴 고객은 3.9회 (7배 차이) → 적립금을 Treatment로 못 쓰는 이유를 데이터로 실증
- B: 구독여부가 회원별로 시간에 따라 변하지 않는 정적 값으로만 관측됨 → "구독의 인과효과"라기보다 "구독군과 비구독군의 재구매 차이의 이질성"이라는 신중한 표현이 필요하다고 지적. 또한 행동 기반 재분류 시 index_date 이후 정보를 쓰면 안 된다고 강조
- **결론**: 구독여부 재분류는 반드시 시점 개념(`index_date`)을 넣어서 설계해야 하고, 최종 리포트에서 "구독시켰더니 재구매가 늘었다"처럼 강한 인과 문구를 쓰지 않도록 팀 전체가 문구 수위를 맞춰야 함.

### 1-3. 이상거래계정(봇/도매상 의심)이 4개 파트 전부에 영향
- A: 구매수량/구매금액 극단치 존재(최댓값 375~377배)
- B: 초고빈도 고객이 K-means centroid를 왜곡할 수 있음
- C: 최다주문 회원(3,113건)이 채소/과일류만 639건 → 계절성 신호 왜곡 가능
- D: 500건 초과 계정 117명이 전체 거래의 11.7% 차지, 소표본 지역(세종·제주)에서 지역×구독 평균이 **역전되는 현상까지 실증**(광주·제주에서 구독자 평균 주문건수가 비구독자보다 낮게 나옴 — 이상계정 영향 추정)
- **결론**: `abnormal_account_flag`를 Step3에서 공통으로 딱 한 번 만들어서 4개 파트가 전부 받아쓰는 구조로 가야 함(각자 만들면 기준이 달라져서 정합성 깨짐).

### 1-4. `연휴여부` 컬럼 불완전 + 특정 날짜 데이터 자체가 없음 (C 신규 발견, 파급력 큼)
- 원본 `연휴여부=True`는 12일뿐이고, 명백한 공휴일인 3/1(삼일절)·10/3(개천절)은 아예 그 날짜의 주문 행 자체가 존재하지 않음(라벨 오류가 아니라 데이터 자체가 없음)
- 그 외 5/14, 6/29, **그리고 11/10~14(5일 연속)**도 원인 불명 결측
- **11/10~14는 8-Step 계획의 홀드아웃 구간(10~11월) 안에 있음** → C뿐 아니라 Step0(무결성 검증)·Step6(Train/Holdout 분할) 전체에 영향 가능. 이건 지금까지 아무도 몰랐던 이슈라 **PM/전체 공유가 우선**.

### 1-5. 기존 위기 서사 수치("-63.8%") 재현 실패 (C 신규 발견)
- 동일 카테고리(과일+채소)로 연휴 전/후 1주 비교 시 오히려 **+8.0%**, 일별 최대 낙폭도 -43.5%~-76.7%로 -63.8%와 정확히 일치하는 조건을 못 찾음
- 원인 후보로 **요일효과 미통제**를 지목(목요일 매출이 다른 요일의 45~55% 수준으로 구조적으로 낮음) — 명절 반동처럼 보이는 게 사실 요일 패턴일 수 있음
- **결론**: 발표자료 문제점 슬라이드(B축 "확인 필요")의 -63.8% 수치를 낸 사람에게 정확한 산출 조건 확인 필요. 이미 슬라이드에도 "확인 필요" 태그가 붙어 있던 항목이라 이번 재현 실패가 그 태그를 뒷받침하는 근거가 됨.

## 2. 파트별 핵심 요약

### A — 가격구간 (구매금액/적립금)
- **구조 발견**: 원본 `구매금액`은 품목가, 장바구니 총액(`basket_amt`) 재계산 필요
- **가설 재검토 제안**: "저가군일수록 반응 크다"는 H1과 반대로, 실측 재구매율은 **역U자형**(Q1 저가 62.9% < Q2·Q3 84~85% > Q4 고가 76.8%) — 저가군이 오히려 참여도가 가장 낮은 이탈위험군
- **핵심 파생변수**: `basket_amt`, `log_basket_amt`, `가격구간`(고객 평균AOV 4분위), `적립금_사용여부`(이진화, Treatment 금지)
- **로그변환 효과**: 구매금액 왜도 27.4 → 0.43(log1p)

### B — 연령×성별 세그먼트
- **분석단위 제안(팀 전체에 적용 권장)**: `회원번호 × index_date` 스냅샷 구조, `preperiod_start`(예: 60~90일 이전)까지의 정보만으로 피처 계산
- **연령대**: `<30/30s/40s/50s/60+` 5구간(30대는 가설 핵심이라 반드시 독립 구간 유지)
- **표본 불균형 경고**: 남성 5.94%(745명), 특히 남성×구독=True는 연령 셀별 14~34명뿐 → 점추정치 순위 비교 금지, CI·표본수 항상 병기
- **N일 기준**: 14일 Primary(양성률 76.0%) / 30일 Sensitivity(양성률 88.3%, ceiling effect 우려)
- **K-means 설계**: 나이+성별만으로 군집 금지(스케일링 여부에 따라 성별이 지배하거나 무시됨) — H4 검증은 사전정의 세그먼트+교호항 회귀로, K-means는 사전 행동피처 기반 보조 분석으로 역할 분리
- **핵심 파생변수**: `age_band_h4`, `gender_h4`, `age_gender_segment`, `index_date`, `treatment_h4`, `treatment_source`, `y_repurchase_14d/30d`, `label_observable_flag`

### C — 계절/명절 상품
- **`계절` 컬럼은 주문월과 1:1**이라 "제철 여부"로 못 씀 → 물품중분류별 월별 판매비중 기반 `제철여부` 신규 파생 필요
- **품목별 계절성 실증**: 수박(6~8월), 참외(3~8월), 딸기(1~5월만), 귤(1,2,9~11월) 등 강한 계절성 확인 vs 당근·양배추는 연중 고름
- **명절선물세트(72종)는 별도 변수로 분리**(단기 집중형이라 신선식품 계절성과 성격 다름)
- **핵심 파생변수**: `제철여부`, `계절성지수`(CV/허핀달), `제철상품구매여부`(행단위), `명절선물세트여부`, `연휴전후구간`, `요일`/`주말여부`(회귀 통제변수로 필수)
- **매핑 기준안**: 제철 판정 임계값(상위3개월 누적비중≥65%), 자체 공휴일 캘린더 보정(3/1·10/3 추가)

### D — 지역×배송조건
- **주소지 정규화 우선순위 최상**: 축약형(`경기`,`광주`,`강원`,`서울` 등 983건, 0.15%)이 정식표기와 분리 집계되고 있어 먼저 고쳐야 함
- **세부주소지는 반드시 주소지와 결합키로**: `동구`,`중구` 등이 6개 광역단위에 걸쳐 중복 — 실제 데이터로 확인됨
- **리드타임으로 배송권역 구분 불가(핵심 발견)**: 지역별 총 리드타임 차이가 최대 0.05일뿐 → "수도권이 인프라 좋아서 효과 클 것"이라는 가정은 리드타임 데이터로 뒷받침 안 됨, 외부지식 기반 매핑 테이블(Tier 1/2/3)이 불가피하며 이건 어디까지나 가정임을 명시해야 함
- **지역별 구독률 2.5배 격차**(세종 21.0% vs 제주 8.2%) → 지역×구독 교호항 분석 시 지역 자체의 구독 성향 차이(자기선택)와 배송조건 효과가 섞일 위험
- **핵심 파생변수**: `region_key`(주소지+세부주소지), `region_tier`(가정 기반 3단계), `is_dawn_delivery_zone`, `is_cancelled_no_delivery`, `is_heavy_account`

## 3. 통합 파생변수 스키마 (8-Step 파이프라인 삽입 위치별)

### Step 1 (컬럼 정제) — D 제안, 전체 선행조건
- 주소지 축약형 → 정식표기 정규화 (D)
- `region_key` = 주소지 + 세부주소지 (세종시 rollup 포함) (D)

### Step 2 (파생변수) — 공통 뼈대
- `index_date`, `preperiod_start`, `label_observable_flag` (B, **팀 공통 채택 권장**)
- `basket_amt`, `basket_item_count`, `log_basket_amt` (A)
- `가격구간`(고객 AOV 4분위, train기간 경계 고정) (A)
- `적립금_사용여부`, `포인트_사용여부`(이진화) (A)
- `age_band_h4`, `gender_h4`, `age_gender_segment`, `age_centered`, `age_sq`, `age_extreme_flag` (B)
- `treatment_h4`(=index_date 시점 구독상태), `treatment_source` (B, **팀 공통 채택 권장**)
- `y_repurchase_14d`(Primary), `y_repurchase_30d`(Sensitivity) (B, **팀 공통 채택 권장 — A/C/D 모두 같은 Y를 공유하므로**)
- `제철여부`, `계절성지수`, `제철상품구매여부`, `명절선물세트여부`, `연휴전후구간`, `연휴명`, `요일`, `주말여부` (C)
- `region_tier`, `is_dawn_delivery_zone`, `is_free_shipping_zone`, `delivery_leadtime_days` (D)

### Step 3 (이상치 플래그) — 4파트 공통 요청, 한 곳에서만 생성
- `abnormal_account_flag`(회원 단위 주문건수 상위1% 또는 500건 초과) — A·B·C·D 전부 참조
- `amount_outlier_flag`(구매금액/AOV IQR 기준)
- `is_cancelled_no_delivery`(D)

### Step 4 (결측 처리)
- 구독여부: False 대치 금지 → 행동기반 재분류(단, index_date 이전 정보만, B 원칙 전체 적용)
- 배송시작/완료일 결측: 주문취소와 100% 일치 확인(D) → 대치 아닌 구조적 상태로 처리
- 성별 결측 1명: Unknown 유지, 대치 금지(B)
- 주소지/세부주소지 결측(절대량 적음): 미상 카테고리 또는 행 제외(D)

### Step 5 (인코딩/스케일링)
- `log1p` 계열: `log_basket_amt`(A), K-means 투입용 금액·빈도 변수(B)
- K-means 피처에는 Treatment·Y 절대 포함 금지(B)
- Target/Frequency Encoding 시 소표본 지역 스무딩 필수(D, 지역 표본 최대 17배 격차)

### Step 6 (Train/Holdout 분할)
- 1~9월 학습 / 10~11월 홀드아웃 원칙 유지 + **N일 라벨 관측을 위한 cutoff 적용**(B가 구체적 날짜까지 계산: N=14일이면 Train index_date ≤ 9/16, Holdout index_date ≤ 11/2)
- **11/10~14 결측 구간이 홀드아웃 안에 있어 cutoff 재검토 필요**(C 발견, 1-4절)

### Step 7 (최종 검증)
- 기존 수치(377배, 54%, 78.7% 등) 재현 + **"-63.8%" 재검증 결과도 이 단계에서 포함**(C 발견, 1-5절)
- 세그먼트별 n/treated/control/positive_rate/CI 출력 표준 포맷 채택(B가 구체적 템플릿 제시, H1~H4 공통 사용 권장)

## 4. 팀 회의에서 바로 쓸 수 있는 액션 아이템

1. **PM/전체 공유**: 11/10~14 데이터 결측(홀드아웃 구간), "-63.8%" 재현 실패 — 이 둘은 지금 몰랐던 새 이슈라 가장 먼저 공유
2. **분석단위를 `회원번호×index_date`로 통일할지 팀 투표** — B의 제안을 A/C/D도 따를지 결정 (따르지 않으면 Y·Treatment 시점 불일치 위험)
3. **N일 기준 14일로 확정할지 결정** — 확정되면 A/C/D의 Uplift·회귀 분석도 전부 이 Y를 그대로 사용

5. **D의 배송권역 Tier / C의 제철 임계값 65%** — 가정 기반임을 최종 보고서에 명시하고 시간 남으면 민감도 분석 병행
