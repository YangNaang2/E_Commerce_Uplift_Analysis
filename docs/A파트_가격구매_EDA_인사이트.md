## 0. 분석 전 구조 확인 (전체 팀에 영향, A파트에서 먼저 발견)

`merged_master.csv`의 1행 = **품목(주문상품) 단위**이지 **주문(장바구니) 단위가 아님**을 확인했다. 같은 회원번호·같은 주문일시로 묶었을 때:

| 구분 | 값 |

**의미**: 원본 `구매금액` 컬럼은 "그 주문에서 산 특정 품목 하나의 가격"이다. 고객의 "가격 민감도"나 "얼마짜리를 사는 고객인가"를 보려면 품목가 그대로가 아니라 **주문(장바구니) 단위로 합산한 총액(이하 `basket_amt`)** 을 기준으로 삼아야 한다. 이 구분을 안 하면 장바구니에 물건을 많이 담은 고객이 "가격이 비싼 걸 사는 고객"으로 잘못 분류된다. 아래 1~2절은 품목 단위와 주문 단위를 모두 계산해서 비교했다.

## 2. 구매금액/적립금과 재구매(타깃) 간 상관성

재구매 프록시로 "고객이 주문(basket)을 2회 이상 했는가"를 잠정 사용했다(정식 Y=재구매여부(N일내)는 팀 공통 2단계에서 확정 예정이므로 여기선 방향성 확인용).

### 2-1. 재구매 간격 (팀 공통 Y 설계에 참고할 근거)

| 기준 | 중앙값 | 평균 | p90 |
|---|---|---|---|
| 품목단위로 계산(오류) | 0일 | 3.3일 | 8일 |
| **주문(basket)단위로 계산(정정)** | **5일** | 11.4일 | 25일 |

품목단위로 diff를 구하면 한 주문 안 여러 품목이 같은 날짜라 간격이 대부분 0으로 나오는 착시가 생긴다. **주문 단위 중앙값 5일**이 실제 재구매 주기이며, 이는 목표 슬라이드의 "30일 이상 무구매 = 평균 주기의 6배" 서술(5일×6≈30일)과 정확히 맞아떨어진다. → **Y=재구매여부(N일내) 설계는 basket 단위 간격을 기준으로 확정**했고, 팀 전체 파이프라인에 반영했다.

### 2-2. 고객 평균 주문총액(AOV) 4분위별 재구매율 — H1 가설 직접 검증

| 구간 | 평균 AOV | 고객 수 | 재구매율(주문 2회+) | 평균 주문 횟수 | 재주문 간격(중앙값) |
|---|---|---|---|---|---|
| Q1(저가) | 12,422원 | 3,136명 | **62.9%** | 8.5회 | 7일 |
| Q2 | 24,288원 | 3,114명 | 83.9% | 16.0회 | 6일 |
| Q3 | 37,389원 | 3,124명 | **84.5%(최고)** | 19.9회 | 5일 |
| Q4(고가) | 75,605원 | 3,125명 | 76.8% | 16.8회 | 5일 |

**H1 가설("저가군일수록 반응 클 것")과 반대되는 패턴이 나왔다.** 재구매율은 저가↔고가 양끝이 아니라 **가운데(Q2~Q3)가 가장 높은 역U자형**이며, 오히려 **Q1(저가) 고객이 재구매율도 가장 낮고 재주문 간격도 가장 길다** — 즉 저가 구매군은 "가격에 민감해서 자주 오는 활발한 고객"이 아니라 **참여도가 가장 낮은 이탈위험군에 가깝다.** 이 발견을 계기로 H1을 "저가군일수록 프로모션에 크게 반응(민감도 가설)"이 아니라 "가격구간별로 반응이 다르다(방향은 열어두고 검증)"는 형태로 재정의해 실제 모델링에 반영했다 — 결과적으로 1위 구간은 Q3(로지스틱) 또는 Q4(RandomForest)로 나와, 이 EDA에서 확인한 "저가군=반응 최대가 아니다"라는 방향과 일치했다(`모델링_통합결과_H1_H4.md` 1절).

### 2-3. 적립금 사용 여부와 AOV — 집계 단위에 따라 수치가 크게 달라짐

| 집계 단위 | 미사용 AOV | 사용 AOV | 증가율 |
|---|---|---|---|
| 품목 단위 (기존 브리핑 수치와 일치) | 11,549원 | 16,928원 | +46.6%(≈기존 "+47%") |
| **주문(basket) 단위** | 35,660원 | **65,839원** | **+84.6%** |

주문 단위로 다시 보니 효과가 기존에 알려진 것보다 훨씬 크다. 다만 이 차이가 "적립금을 써서 더 많이 산 것"인지 "원래 많이 사는 고객이 적립금도 많이 갖고 있어서 쓴 것"인지는 이 데이터만으로 구분이 안 된다.

### 2-4. ⚠️ 적립금 사용 이력과 구매 빈도 — 자기선택편향의 실증

| 구분 | 평균 주문 횟수 | 중앙값 |
|---|---|---|
| 적립금 한 번도 안 씀 | 3.86회 | 2회 |
| 적립금 한 번이라도 씀 | **25.94회** | **17회** |

거의 7배 차이다. 이건 적립금이 재구매를 유도했다기보다, **원래 자주 사는 충성고객일수록 적립금이 쌓여서 쓸 기회도 많아진 것**일 가능성이 매우 크다(역인과). CLAUDE.md에 이미 정리된 "Treatment 컬럼 부재 → 자기선택편향" 리스크를 실제 숫자로 확인한 셈이며, **적립금 사용여부를 그대로 Treatment로 쓰면 안 되고 Treatment=구독여부로 대체한 기존 결정이 옳았다는 근거**로 쓸 수 있다.

## 3. A파트 핵심 파생변수 아이디어 (4가지)

| # | 파생변수 | 정의 | 도출 논리 |
|---|---|---|---|
| 1 | `basket_amt`, `basket_item_count` | 회원번호+주문일시로 재집계한 주문(장바구니) 총액·품목수 | 0절에서 확인했듯 원본 `구매금액`은 품목가라 그대로 쓰면 장바구니 크기가 왜곡됨. 모든 가격 관련 분석의 전제 조건. |
| 2 | `log_basket_amt` (= `log1p(basket_amt)`) | 로그변환된 주문총액 | 왜도 9.75→-0.16으로 대칭화 확인. 회귀·클러스터링 입력용 스케일링 변수. 원값은 삭제하지 않고 병행 보관(극단치 분리 방침 준수). |
| 3 | `가격구간`(price_segment) | 고객별 **평균 basket_amt(AOV)** 기준 4분위 라벨(Q1~Q4) | 개별 주문 하나의 금액은 변동이 크지만(같은 고객도 소량/대량 구매 섞임), 고객 평균 AOV는 상대적으로 안정적인 "그 고객이 평소 얼마짜리를 사는 사람인가"를 나타내는 특성이라 세그먼트 정의에 적합. H1의 교호항 회귀·Uplift 세그먼트에 직접 투입. |
| 4 | `적립금_사용여부`, `적립금_사용이력(누적횟수/최근성)` | 연속값 대신 이진 플래그 + 누적 사용 횟수 | 95%+가 0이라 연속값 자체는 정보가 희박함. 단, 2-4절에서 확인했듯 이 변수는 **자기선택편향이 강해 Treatment로 쓰지 말고 설명/세그먼트 변수로만 사용**해야 함을 명시해서 병합.|

(보너스, 시간 남으면) `basket_item_count` 기반 `다품목_주문여부` — 구매수량 자체보다 이게 더 안정적인 신호일 수 있음.

## 4. 공통 8-Step 파이프라인 병합용 함수 스케치

Step 1(컬럼 정제)~2(파생변수) 사이에 아래 순서로 끼워 넣으면 됨. 다른 파트(B/C/D)가 만들 함수와 나란히 하나의 스크립트에 이어붙이는 걸 전제로, 회원번호/주문일시 키만 맞춰서 작성함.

```python
import numpy as np
import pandas as pd

def build_basket_table(df: pd.DataFrame) -> pd.DataFrame:
    """Step 1~2: 품목단위(df) -> 주문(basket)단위 재집계. 이후 모든 A파트 피처의 기반."""
    df = df.copy()
    df["주문일시_dt"] = pd.to_datetime(df["주문일시"])
    valid = df[df["주문취소여부"].isna()]  # 취소건 제외
    basket = valid.groupby(["회원번호", "주문일시_dt"]).agg(
        basket_amt=("구매금액", "sum"),
        basket_item_count=("구매금액", "size"),
        basket_reward_used=("사용 적립금", lambda s: int((s > 0).any())),
    ).reset_index()
    return basket


def add_log_price_features(basket: pd.DataFrame) -> pd.DataFrame:
    """Step 2: 스케일링용 파생변수. 원본 basket_amt는 유지(극단치 분리 방침)."""
    basket = basket.copy()
    basket["log_basket_amt"] = np.log1p(basket["basket_amt"])
    return basket


def add_price_segment(basket: pd.DataFrame, train_only_mask: pd.Series = None) -> pd.DataFrame:
    """Step 2: 회원별 평균 AOV 기준 4분위 가격구간(H1용).
    ⚠️ Step 6(Train/Holdout 시간분할)과 순서 주의:
       분위수 경계는 반드시 '학습기간(1~9월)' 데이터로만 산출해서 홀드아웃(10~11월)에 동일 적용할 것
       (미래 데이터로 경계를 정하면 정보 누수).
    """
    basket = basket.copy()
    mem_aov = basket.groupby("회원번호")["basket_amt"].mean().rename("aov")
    ref = mem_aov[train_only_mask] if train_only_mask is not None else mem_aov
    bins = pd.qcut(ref, 4, retbins=True)[1]          # 학습기간 기준 경계 확정
    mem_aov_seg = pd.cut(mem_aov, bins=bins, labels=["Q1_저가", "Q2", "Q3", "Q4_고가"], include_lowest=True)
    basket = basket.merge(mem_aov_seg.rename("가격구간"), on="회원번호", how="left")
    return basket


def add_reward_usage_features(df_item: pd.DataFrame) -> pd.DataFrame:
    """Step 2: 적립금/포인트 이진화 + 누적 이력. Treatment로는 사용 금지, 설명변수로만 사용."""
    df_item = df_item.copy()
    df_item["적립금_사용여부"] = (df_item["사용 적립금"] > 0).astype(int)
    df_item["포인트_사용여부"] = (df_item["사용 포인트 네이버"] > 0).astype(int)
    return df_item
```

**병합 시 순서 제안**: `build_basket_table` → `add_log_price_features` → `add_price_segment`(홀드아웃 분할 확정 후 재호출) 순으로 파이프라인에 삽입하고, `add_reward_usage_features`는 품목단위 테이블(df_item)에 바로 적용 후 basket 집계에 흡수.

## 5. 팀 전체에 반영된 이슈 (A파트 발견, 공통 영향)

1. **재구매 간격(Y 설계 기준)은 반드시 주문(basket) 단위로 계산해야 함** — 품목단위로 계산하면 중앙값이 0으로 왜곡됨(2-1절). 팀 공통 Y(재구매여부 14일내) 설계의 근거가 됐다.
2. **H1 가설의 방향을 재정의**: 저가군이 반응이 큰 게 아니라 재구매율·빈도가 가장 낮은 이탈위험군으로 보여(2-2절), "저가군이 민감도가 높다"가 아니라 "가격구간별로 반응이 다르다(방향은 열어두고 검증)"는 형태로 재정의해 반영했다.
3. **적립금 사용여부는 자기선택편향이 강함**(2-4절, 7배 차이) — Treatment로 쓰지 않고 구독여부로 대체한 기존 결정을 데이터로 재확인했다.
